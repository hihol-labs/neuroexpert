# UX/UI-аудит маркетингового сайта НейроЭксперт

Дата: 2026-05-11

## Объём проверки

Проверены ключевые публичные страницы:

- `/` — главная;
- `/for-business` — страница для локального бизнеса;
- `/how-it-works` — сценарии работы для бизнеса и эксперта;
- `/for-experts` — страница для индивидуальных экспертов;
- `/pricing` — тарифы;
- `/launch`, `/audit`, `/scan`, `/for-agencies` — связанные точки входа;
- общие маркетинговые компоненты: навигация, футер, продуктовые визуальные блоки.

## Краткий вывод

После апгрейда сайт стал значительно ближе к нужной продуктовой логике:

> НейроЭксперт показывает, где бизнес теряет клиентов и деньги, а затем превращает найденные потери в задачи, страницы, отзывы, возврат обращений и рост продаж.

Главная проблема прежней версии была в смешении сценариев: экспертный контур и B2B-контур шли вперемешку. Теперь сценарии разведены: бизнес видит свою систему локальных продаж, эксперт видит путь от спроса к странице и записи.

## Что было исправлено

### 1. Главная страница

Было:

- слишком много блоков и смыслов на одной странице;
- B2B, эксперт, карты, нейросети, отчёты, модули и ниши конкурировали за внимание;
- визуально сайт ощущался скорее как “AI-стартап”, чем как система продаж.

Стало:

- первый экран сразу говорит: “Найдём, где бизнес теряет клиентов, и запустим рост продаж”;
- справа показан отчёт “Карта потерь за 7 дней”;
- ниже два понятных входа: “Для бизнеса” и “Для эксперта”;
- добавлен блок “Мы понимаем, где теряются деньги”;
- оставлены только сильные продуктовые доказательства: карта потерь, задачи, отчёт за 7 дней, оценка недополученной выручки.

### 2. `/how-it-works`

Было:

- сначала экспертный сценарий;
- потом B2B;
- потом снова экспертные модули;
- пользователь из бизнеса терял нить.

Стало:

- один переключатель аудитории: “Для бизнеса” / “Для эксперта”;
- для бизнеса показаны только бизнесовые шаги: точки входа, потери, задачи, измерение;
- для эксперта показан отдельный путь: спрос, голос, страница, публикация, результат;
- B2B и экспертный сценарий больше не смешиваются в одном потоке.

### 3. `/for-business`

Было:

- встречались непонятные англицизмы;
- были формулировки вроде `cockpit`, `lost leads`, `follow-up`, `Setup`, `Local Sales Audit`;
- часть страницы звучала как внутренний продуктовый документ.

Стало:

- “Панель собственника” вместо `cockpit`;
- “потерянные обращения” вместо `lost leads`;
- “повторные касания” вместо `follow-up`;
- “аудит продаж” вместо `Local Sales Audit`;
- “запуск за 30 дней” вместо `Setup`;
- “ответы нейросетей” вместо сухого `AI-выдача`.

### 4. Цветовая палитра и заставка

Было:

- много cyan/blue/purple glow;
- фон воспринимался как декоративная нейросетевая заставка;
- визуальный тон был ближе к “модному AI”, чем к “системе управления продажами”.

Стало:

- тёмная графитовая база;
- emerald/cyan как рабочий акцент;
- меньше фиолетового и неонового свечения;
- фон стал спокойной продуктовой сеткой;
- интерфейс выглядит взрослее и ближе к B2B.

## Проверка языка

Видимые пользователю англицизмы заменены там, где они мешали пониманию:

| Было | Стало |
|---|---|
| cockpit | панель собственника |
| lost leads | потерянные обращения |
| follow-up | повторное касание |
| Setup | запуск |
| CTA | кнопка заявки / целевое действие |
| Local Sales Audit | аудит продаж |
| Local Sales OS | система локальных продаж / сопровождение продаж |
| AI-ответы | ответы нейросетей |
| dashboard | личный кабинет / панель |

В коде могут оставаться английские имена компонентов и переменных. Они не видны пользователю и не влияют на UX.

## Проверка B2B-доверия

Сайт теперь показывает B2B-клиенту:

- где клиентский поток появляется: карты, поиск, Авито, отзывы, сайт, нейросети, звонки;
- где поток теряется: слабые карточки, конкуренты, пропущенные обращения, слабые отзывы;
- что получает владелец: карту потерь, задачи, оценку выручки под риском;
- как будет внедрение: аудит, запуск, сопровождение;
- почему это связано с деньгами: каждый вывод привязан к обращению, спросу, конкуренту или среднему чеку.

Это повышает доверие сильнее, чем абстрактные обещания “мы настроим маркетинг”.

## Проверка экспертного сценария

Экспертный контур теперь выглядит отдельным и понятным:

- система находит спрос;
- эксперт отвечает голосом;
- ответ превращается в страницу;
- страница ведёт к записи;
- результат измеряется по показам, кликам, заявкам и упоминаниям в нейросетях.

Это не конфликтует с B2B-контуром, потому что подаётся как второй сценарий внутри одной платформы.

## Проверка конверсии

Основные действия стали логичнее:

- главный B2B-призыв: “Получить аудит продаж”;
- экспертный призыв: “Получить карту спроса”;
- общий призыв: “Как это работает”;
- тарифная страница ведёт отдельно к бизнесовым пакетам и тарифам для экспертов;
- форма B2B собирает город, нишу, площадки, конкурентов, средний чек и потери.

## Техническая проверка

Пройдено:

- `pnpm --filter web exec tsc --noEmit --pretty false`;
- `pnpm --filter web lint`;
- `git diff --check`;
- `pnpm --filter web build`;
- локальная проверка HTTP 200 на `http://127.0.0.1:3002/`;
- браузерная DOM-проверка главной, `/for-business`, `/how-it-works`;
- поиск публичных англицизмов по маркетинговым страницам.

Ограничение проверки:

- скриншот через in-app browser не снялся из-за таймаута CDP-команды. DOM-проверка и сборка прошли успешно.

## Остаточные рекомендации

1. После первых 2-3 пилотов добавить реальные кейсы:
   - было;
   - нашли потери;
   - сделали;
   - что изменилось;
   - какие обращения вернули.

2. Добавить реальные скриншоты личного кабинета, когда B2B-кабинет будет готов:
   - динамика видимости;
   - задачи;
   - конкуренты;
   - потерянные обращения;
   - отзывы.

3. Для максимального доверия добавить блок “Как считаем выручку под риском”:
   - обращения без ответа;
   - средний чек;
   - вероятность возврата;
   - потенциальная выручка.

4. Не возвращать в публичный язык лишние англицизмы. Исключения допустимы только для агентской страницы и API-документации, где аудитория техническая.
